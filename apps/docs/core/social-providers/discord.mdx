---
title: "Sign in with Discord"
description: "Let people use their Discord account to sign in to Tracing."
---

This sets up sign-in for your instance. It does not connect a repository or send project notifications.

## Register the application

Open the [Discord developer console](https://discord.com/developers/applications). Create an application, open **OAuth2**, and add the address below under redirects. Copy the OAuth client ID and secret.

For a bundled Tracing deployment at `https://kaneo.example.com`, the callback is:

```text
https://kaneo.example.com/api/auth/callback/discord
```

Use your own hostname. If the API is hosted separately, use its public origin instead. The callback path is `/api/auth/callback/discord`; do not append a second `/api` when your API URL already includes it.

For provider-specific options, see the [official OAuth guide](https://docs.discord.com/developers/topics/oauth2).

## Configure Tracing

Add the values from the provider to your server's `.env`:

```env
DISCORD_CLIENT_ID=your-client-id
DISCORD_CLIENT_SECRET=your-client-secret
```

Apply the change to the bundled deployment:

```bash
docker compose up -d --force-recreate kaneo
```

## Test sign-in

Open Tracing in a private browser window and choose the Discord sign-in option. Complete authorization and confirm you return to Tracing.

If the provider reports a redirect mismatch, compare the full URL, including the scheme, hostname, port, and path. If sign-in succeeds but joining a workspace fails, check the invitation email and instance registration settings.

## Turn it off

Remove the two environment variables and recreate Tracing. Make sure people have another way to sign in before disabling the provider. Review [access settings](/core/installation/environment-variables#access-control) before enforcing SSO-only access.
