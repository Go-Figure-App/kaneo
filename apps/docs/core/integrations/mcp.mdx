description: Connect Tracing to MCP clients like Cursor and Claude Desktop using the official Tracing MCP server.

Tracing supports the Model Context Protocol (MCP) in two ways:

1. **Built-in HTTP endpoint**: every Tracing instance exposes `/api/mcp` out of the box. No extra setup, no extra process.
2. **Local stdio server**: build the `@tracing/mcp` workspace package from this repository. It is not published to npm.

Both offer the same tools for managing workspaces, projects, tasks, custom fields, comments, and labels.

To work with Tracing from a terminal or a shell script instead, use the [Tracing CLI](/cli).

## Built-in HTTP endpoint

Every Tracing API instance ships with a Streamable HTTP MCP endpoint. This is the recommended approach for self-hosted deployments.

Point your MCP client at:

```
https://tracing.example.com/api/mcp
```

With an OAuth-capable client, you will be redirected to Tracing to sign in and explicitly approve the MCP client. After approval, all MCP tools run as your authenticated user.

The endpoint implements OAuth 2.1 with PKCE for authentication. Discovery metadata is available at:

- `/.well-known/oauth-protected-resource/api/mcp`
- `/.well-known/oauth-authorization-server/api`

The endpoint serves both MCP protocol eras without server-side sessions. Modern
`2026-07-28` requests are self-contained; 2025-era clients still send
`initialize`, but Tracing does not issue a session ID. See [MCP protocol
reference](/core/integrations/mcp-stateless) for transport behavior, proxy
requirements, and request limits.

## Stdio package

The `@tracing/mcp` package runs a local stdio MCP server and authenticates with Tracing using device authorization. Use this when your MCP client requires stdio transport.

### Prerequisites

- Node.js 24 or newer
- A running Tracing API
- Access to the Tracing web app to approve device login

Build from the repository using its locked dependencies:

```bash
pnpm install --frozen-lockfile
pnpm --filter @tracing/mcp build
TRACING_API_URL=https://tracing.gofigureapp.io node packages/mcp/dist/index.js serve
```

Configure a stdio client to run `node` with the absolute path to
`packages/mcp/dist/index.js` followed by `serve`, and set `TRACING_API_URL` in
that client's environment. The built-in HTTP endpoint is simpler for clients
that support it. The interactive package installer assumes registry distribution;
use this explicit source command until a package release exists.

The default device client is `tracing-mcp`; `tracing-cli` and legacy Kaneo device
clients are also allowed by default. On first use, open the printed verification
URL and approve the device. New credentials use `~/.config/tracing-mcp` (or the
matching `XDG_CONFIG_HOME` directory). Existing `kaneo-mcp` credentials remain
usable for the same server. `TRACING_API_KEY` can provide an existing API key for
a headless client. Keep keys in the client's secret configuration.

## Available tools

Both the HTTP endpoint and stdio package expose the same tools:

- Session: `whoami`, `list_workspaces`, `list_workspace_members`, `list_notifications`
- Search: `search`
- Projects: `list_projects`, `get_project`, `create_project`, `update_project`, `list_project_columns`
- Tasks: `list_tasks`, `get_task`, `get_task_by_ticket_id`, `create_task`, `duplicate_task`, `update_task`, `delete_task`, `move_task`, `update_task_status`, `update_task_assignee`, `update_task_due_date`, `update_task_recurrence`, `list_task_activity`
- Custom fields: `list_project_custom_fields`, `get_task_custom_field_values`, `set_task_custom_field_value`
- Time entries: `list_task_time_entries`, `get_time_entry`, `create_time_entry`, `update_time_entry`
- Comments: `list_task_comments`, `create_task_comment`, `update_task_comment`, `delete_task_comment`
- Labels: `list_workspace_labels`, `create_label`, `attach_label_to_task`, `detach_label_from_task`, `delete_label`
- Task relations: `create_task_relation`, `get_task_relations`, `delete_task_relation`

Use `get_task_by_ticket_id` with a key such as `KAN-12` to fetch one task directly. If the same key identifies multiple accessible tasks, pass `workspaceId` or `projectId` to select one.

`list_project_columns` is worth calling first when setting a status: the column
slugs it returns are exactly the values `create_task` and `update_task_status`
accept. Likewise `list_workspace_members` resolves the user IDs the assignee
tools expect. Time entries have no delete endpoint on the API, so there is no
`delete_time_entry` tool.

`get_task` and `list_tasks` don't include custom field values. Call
`list_project_custom_fields` for a project's field IDs, types, and options, and
`get_task_custom_field_values` for one task's values. `set_task_custom_field_value`
takes a string, number, or boolean, an array of options for a multiselect field,
or `null` to clear the value. Dates use `YYYY-MM-DD`.

## Debugging

To run the stdio server directly:

```bash
node packages/mcp/dist/index.js serve
```

When running from source in this monorepo:

```bash
pnpm --filter @tracing/mcp run build
pnpm --filter @tracing/mcp run start
```
