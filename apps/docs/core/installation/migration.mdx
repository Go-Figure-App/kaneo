---
title: Move to the bundled container
description: Replace separate API and web containers while keeping your existing database and configuration.
---

Use this guide only if your deployment still has separate `ghcr.io/usekaneo/api` and `ghcr.io/usekaneo/web` services. Build `Dockerfile.tracing` from this repository; its bundled image serves both on port 5173. Tracing registry images are not published.

If you already use the bundled image, follow [Upgrade Tracing](/core/operations/upgrades). For drim-managed deployments, see [Migrate to drim](/core/installation/drim-migration).

## Before changing the layout

1. [Back up the database, uploaded files, and configuration](/core/operations/backups). Test that you can restore the database.
2. Record the existing image version and choose a target release after reading its release notes.
3. Keep the same Compose project name, database volume, PostgreSQL major version, database credentials, and `AUTH_SECRET`.
4. Save copies of your Compose file, `.env`, and reverse-proxy configuration.

Changing the application layout does not require replacing PostgreSQL or moving its data. A newer Tracing image can run database migrations, so an older image alone is not a complete rollback.

## Replace the application services

In your existing Compose file, replace `api` and `web` with this service. Build a reviewed source commit with `docker build -f Dockerfile.tracing -t tracing:local .`. Keep the existing database service and volumes.

```yaml
  tracing:
    image: tracing:local
    env_file: .env
    ports:
      - "127.0.0.1:5173:5173"
    restart: unless-stopped
```

This port binding assumes your reverse proxy runs on the host. If the proxy is another container, attach Tracing to its network and point it at `http://tracing:5173` instead. Preserve any existing networks needed to reach the database or storage.

Set `TRACING_CLIENT_URL` to your public web origin. In a same-origin deployment, remove an old `TRACING_API_URL` override that points to the separate API service: the bundled entrypoint derives `TRACING_CLIENT_URL` plus `/api`.

Keep `DATABASE_URL` if it already identifies the correct database. Alternatively, the bundled image can derive it from `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `POSTGRES_HOST` (default `postgres`), and `POSTGRES_PORT` (default `5432`). Preserve the existing values; changing an environment variable does not rename a database or reset its password.

Keep your existing `AUTH_SECRET`. Generating a new one invalidates existing sessions.

## Switch traffic

Validate the edited file and build the selected source revision before stopping the old application:

```bash
docker compose config --quiet
docker build -f Dockerfile.tracing -t tracing:local .
```

Stop the old `api` and `web` services using your saved Compose file. Start the new service:

```bash
docker compose up -d tracing
docker compose logs --tail=100 tracing
```

Update your proxy to send web, API, and WebSocket requests to port 5173. See [Nginx and HTTPS](/core/reverse-proxy/nginx). Remove dependencies on the old service names from other services in your Compose file.

Check `/api/health` through the public URL, then sign in, open an existing project, edit a test task, and check an existing attachment. Remove the stopped API and web containers only after those checks pass. Keep your backups.

## Migrating an old Helm values file

The bundled chart uses `tracing.*` values. Old split-container charts used `api.*` and `web.*`. Compare your file with the [values for your selected chart release](https://github.com/Go-Figure-App/tracing/tree/main/charts/tracing) before upgrading.

| Old setting | Bundled chart setting |
| --- | --- |
| `api.image.*` | `tracing.image.*`, with repository `tracing` |
| `api.resources` | `tracing.resources` |
| `api.env.*` | Corresponding settings under `tracing.env` |
| `api.livenessProbe` / `api.readinessProbe` | `tracing.livenessProbe` / `tracing.readinessProbe` |
| Separate API and web services | One `tracing.service`, port 5173 |
| Ingress targets for API and web | Bundled Tracing service on port 5173 |

Check the probes as well as their key names: current probes use `/api/health` and the named port `tracing`. Keep your PostgreSQL PVC and existing credential secrets. The default image is the source-built `tracing:local`.

Render the chosen chart with your migrated values and inspect its services, ingress, secrets, and database configuration before applying it. Keep the old release name, namespace, database credentials and PVC. Set `nameOverride: kaneo` if the old chart used its default name, and preserve any existing `fullnameOverride` so immutable selectors and resource names stay stable. See the chart README for the rename upgrade checklist.

## Recovery

If the new application never changed the database, restore the old application and proxy configuration. If it applied migrations, restore the matching database backup before returning to the old version. Follow the [restore procedure](/core/operations/backups) and keep the failed database available for investigation.
