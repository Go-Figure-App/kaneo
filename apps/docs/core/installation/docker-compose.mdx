title: "Install with Docker Compose"
description: "Run Tracing and PostgreSQL, then sign in to your new instance."
---

This guide builds a local instance at `http://localhost:5173`. You need Docker
with Compose V2. Tracing container images are currently built from this source
repository; no Tracing registry image is published.

## 1. Clone the source

```bash
git clone https://github.com/Go-Figure-App/tracing.git
cd tracing
```

Use the included `compose.yml`, which builds `Dockerfile.tracing` as
`tracing:local`. This guide requires changing its port mapping to
`127.0.0.1:5173:5173` before starting it, so the local trial is bound to loopback.

## 2. Add configuration

Run this twice to generate two different secrets:

```bash
openssl rand -hex 32
```

Create `.env` beside `compose.yml`. Replace both placeholders with the generated values:

```env
TRACING_CLIENT_URL=http://localhost:5173
POSTGRES_DB=kaneo
POSTGRES_USER=kaneo
POSTGRES_PASSWORD=replace-with-the-first-generated-secret
AUTH_SECRET=replace-with-the-second-generated-secret
```

Keep this file private. On Linux or macOS, run `chmod 600 .env`.

The bundled image derives its database connection from `POSTGRES_*` and its API URL from `TRACING_CLIENT_URL`. You do not need to set `DATABASE_URL` or `TRACING_API_URL` for this setup.

## 3. Start and check the services

```bash
docker compose up -d --build
docker compose ps
curl --fail http://localhost:5173/api/health
```

Allow time for the first database initialization and migrations. Both services should become healthy. If they do not, check:

```bash
docker compose logs --tail=100 tracing postgres
```

Open [localhost:5173](http://localhost:5173), create the initial account, and follow [Your first project](/core/index).

## 4. Make it available to your team

The port is bound to the host's loopback address. To serve Tracing on a domain, follow the [Nginx and HTTPS guide](/core/reverse-proxy/nginx), then set:

```env
TRACING_CLIENT_URL=https://tracing.example.com
```

Apply environment changes by recreating the container:

```bash
docker compose up -d --force-recreate tracing
```

A plain restart keeps the old environment. If you use a proxy in another container, connect it to Tracing's Docker network and proxy to `tracing:5173` instead of the host's loopback address.

## Keep secrets in files

Instead of putting `POSTGRES_PASSWORD` and `AUTH_SECRET` in `.env`, you can mount them as Docker secret files. The source build includes `_FILE` support.

Move the values you already use from `.env` into their own files:

```bash
mkdir -p secrets
sed -n 's/^POSTGRES_PASSWORD=//p' .env > secrets/postgres_password
sed -n 's/^AUTH_SECRET=//p' .env > secrets/auth_secret
chmod 700 secrets
chmod 644 secrets/*
```

Keep the current values. PostgreSQL sets its password only when it first initializes the `postgres_data` volume, so a new value in the file would no longer match the database. A new `AUTH_SECRET` would also sign everyone out. Generate fresh values with `openssl rand -hex 32` only for a new installation that has not started yet.

Compose mounts these files with their host ownership, and the containers read them as non-root users (UID 1001 for Tracing, `postgres` for PostgreSQL). The files therefore need to be readable by other users, while the `700` directory keeps other accounts on the host from reaching them.

Remove `POSTGRES_PASSWORD` and `AUTH_SECRET` from `.env`. In `compose.yml`, replace the `POSTGRES_PASSWORD` line of the `postgres` service and add the secrets to both services:

```yaml
services:
  postgres:
    environment:
      POSTGRES_USER: ${POSTGRES_USER:-kaneo}
      POSTGRES_DB: ${POSTGRES_DB:-kaneo}
      POSTGRES_PASSWORD_FILE: /run/secrets/postgres_password
    secrets:
      - postgres_password

  tracing:
    environment:
      POSTGRES_PASSWORD_FILE: /run/secrets/postgres_password
      AUTH_SECRET_FILE: /run/secrets/auth_secret
    secrets:
      - postgres_password
      - auth_secret

secrets:
  postgres_password:
    file: ./secrets/postgres_password
  auth_secret:
    file: ./secrets/auth_secret
```

Keep the other keys of each service as they are. For [custom OAuth](/core/social-providers/custom-oauth), mount the client secret the same way and set `CUSTOM_OAUTH_CLIENT_SECRET_FILE`. SMTP, S3, GitHub, Turnstile, billing, and notification secrets work the same way. A direct value in `.env` takes precedence over its `_FILE` variable, so leave the direct variable unset. See the [environment variable reference](/core/installation/environment-variables#authentication) for the full list, how files are read, and what happens when one is missing.

## Optional features

- [Silo](/core/installation/silo) stores images and attachments.
- [SMTP](/core/installation/environment-variables#smtp-configuration) delivers sign-in codes, invitations, and notifications.
- [Sign-in providers](/core/social-providers/custom-oauth) connect your identity provider.

PostgreSQL stays inside the Compose network. Do not publish its port for this deployment.

Before storing work you care about, set up [backups](/core/operations/backups). Use the [upgrade guide](/core/operations/upgrades) when changing versions.
