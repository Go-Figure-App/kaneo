---
title: Sign in
description: Connect the CLI to the Go Figure instance or a self-hosted instance, use API keys in CI, and keep several logins.
---

```bash
tracing login
```

The CLI shows a one-time code, copies it to your clipboard, and opens the approval page of your Tracing web app. Approve the request there and the CLI saves the login. After signing in you can choose a default workspace. Pass `--no-browser` to print the link instead of opening a browser.

For a self-hosted instance, pass its address once. Later commands reuse it:

```bash
tracing login --api-url https://tracing.example.com
```

`tracing login` uses [device authorization](/api-reference/authentication) with the `tracing-cli` client ID, which Tracing allows by default. If you set `DEVICE_AUTH_CLIENT_IDS`, add `tracing-cli` to that explicit list and retain `kaneo-cli` so older CLI releases can still sign in.

Check or end the session with:

```bash
tracing whoami
tracing logout
```

## API keys for CI and scripts

Create a key in **Settings → Account → API Keys** and set it in the environment:

```bash
export TRACING_API_KEY=your-key
tracing task list -w your-workspace-id -p KAN
```

The CLI picks credentials in this order: `--token`, then `TRACING_API_KEY`, then the stored login. A stored login is only ever sent to the server it was created for. A few account-level actions need a signed-in session, and the CLI tells you when an API key cannot be used.

## Profiles

Each login is stored as a profile. The first one is called `default`. To keep a second server or account, sign in with another profile name:

```bash
tracing login --profile work --api-url https://tracing.example.com
tracing profile list
tracing profile use default
```

`tracing login` and `tracing profile use` make that profile the active one. To use a profile for a single command, pass `--profile work` or set `TRACING_PROFILE=work`. `tracing profile rename` and `tracing profile remove` manage the rest.
