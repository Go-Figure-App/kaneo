The CLI uses JSON mode when you pass `--json` or `--jq`, set `TRACING_JSON=true`, or pipe its output:

- A successful command prints exactly one JSON value on stdout.
- A failed command prints `{"error": "message"}` on stdout and exits with code 1.
- JSON mode never prints colors, spinners, progress lines or images.

```bash
tracing task list -p KAN --json | jq '.[] | select(.priority == "urgent") | .ticketId'
```

Pass `--human` to force styled output. Styled output respects `NO_COLOR`, `FORCE_COLOR` and `TERM=dumb`, and uses plain ASCII when the terminal cannot show Unicode. Ticket IDs and project names are clickable links in terminals that support them.

## Filter with `--jq`

`--jq` filters the JSON output with a jq expression. The engine is built in, so you do not need `jq` installed. Each result goes on its own line, and strings print without quotes:

```bash
tracing task list -p KAN --jq '.[].ticketId'
tracing task list -p KAN --jq '.[] | select(.priority == "urgent") | .ticketId'
tracing task view KAN-12 --jq '.url'
tracing task mine --jq '.[] | {ticketId, dueDate}'
```

An invalid expression fails before any request is sent. Run the same command with `--json` to see the data the expression receives.

## Long text and stdin

Comments and descriptions can come from a file or from stdin. Pass `-F <file>` to read a file, or `-` to read stdin:

```bash
tracing comment add KAN-12 -F notes.md
git log -1 --format=%B | tracing comment add KAN-12 -
tracing project edit KAN -F README.md
tracing task create "Write release notes" -p KAN -F notes.md
tracing task attach KAN-12 screenshot.png -m "Before and after"
```

`tracing task create`, `task edit`, `comment add`, `comment edit`, `task attach`, `project create`, `project edit` and `workspace edit` accept `-F`. `tracing comment add` and `tracing task comment` also read stdin when you leave out the text.

## Confirmations

Commands that delete or remove data, such as `tracing task delete` or `tracing label delete`, ask for confirmation in a terminal. Deleting a project asks you to type its key, and deleting a workspace asks for its slug. In scripts, these commands stop with an error until you pass `--yes`:

```bash
tracing task delete KAN-12 --yes
```

## Call the API directly

`tracing api` sends an authenticated request to any Tracing API endpoint, like `gh api` does for GitHub. It uses the same server, credentials and output modes as the other commands. The path is under `/api`, and the `/api` prefix is optional:

```bash
tracing api GET /user/me
tracing api GET /task/assigned --query workspaceId=your-workspace-id
tracing api PUT /task/status/your-task-id -f status=done
tracing api POST /time-entry --input entry.json
```

`-f key=value` builds a JSON body. Values that parse as JSON keep their type, and dotted keys such as `a.b=1` nest. `--input` reads the body from a file, or `-` for stdin. See the [API reference](/api-reference/introduction) for the available endpoints.

## Agent skill

Coding agents such as Claude Code, Codex and Cursor can manage your Tracing work through the CLI. The `tracing-cli` skill shows them how: check the login and workspace first, read the JSON output, address tasks by ticket ID, and confirm with you before deleting anything.

```bash
npx skills add Go-Figure-App/tracing --skill tracing-cli
```

Add `-g` to install it for every project. The skill is a single file in [`skills/tracing-cli`](https://github.com/Go-Figure-App/tracing/tree/main/skills/tracing-cli), so you can also copy it into your agent's skills folder by hand. Agents that should talk to Tracing without a shell can use the [MCP server](/core/integrations/mcp) instead.
