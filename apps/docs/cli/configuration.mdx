Every setting has a flag, an environment variable, or both. A flag wins over its environment variable.

| Setting | Flag | Environment variable |
| --- | --- | --- |
| Server | `--api-url` | `TRACING_API_URL` (default `https://tracing.gofigureapp.io`) |
| Token or API key | `--token` | `TRACING_API_KEY` |
| Workspace | `-w`, `--workspace` | `TRACING_WORKSPACE` |
| Project | `-p`, `--project` | `TRACING_PROJECT` |
| Stored login | `--profile` | `TRACING_PROFILE` |
| JSON output | `--json` | `TRACING_JSON=true` |
| Inline images | | `TRACING_IMAGES` (`kitty`, `iterm`, `blocks` or `off`) |
| Web app address for links | | `TRACING_WEB_URL` (detected during login) |
| Config file | | `TRACING_CONFIG` |

Logins are stored in `~/.config/tracing/config.json`, or `$XDG_CONFIG_HOME/tracing/config.json`, with permissions that only your user can read. If another tracing CLI already uses that file, the official CLI leaves it untouched and asks you to move it or set `TRACING_CONFIG`. The CLI keeps track of your running timer in `timer.json` next to the config file.

## Repository defaults

Link a repository to a workspace and project, so commands run anywhere inside it use them:

```bash
tracing link                     # pick from a list in a terminal
tracing link -w your-workspace-id -p KAN
```

`tracing link` writes a `.tracing.json` at the root of the Git repository, or in the current directory outside a repository. It keeps any other keys already in the file:

```json
{ "workspace": "your-workspace-id", "project": "KAN" }
```

Commands look for `.tracing.json` in the current directory and its parents. `tracing unlink` removes the two keys, and deletes the file when nothing else is left.

The CLI picks the workspace from `-w`, then `TRACING_WORKSPACE`, then `.tracing.json`, then the default you chose with `tracing workspace use`. It picks the project from `-p`, then `TRACING_PROJECT`, then `.tracing.json`.

## Check your setup

`tracing context` shows the server, profile, account, workspace and project in use, and where each one came from. Use it when a command picks the wrong workspace or server.

`tracing doctor` checks the config file, the server, your login, the workspace, and whether the server has every API operation this CLI uses. It exits with code 1 when a check fails, so it also works in CI:

```bash
tracing doctor
```

## Images in the terminal

`tracing task images` shows the images in a task description, `tracing task attach` previews the images you upload, and `tracing whoami` shows your avatar.

- Kitty and Ghostty show full images with the Kitty graphics protocol.
- iTerm2 and WezTerm show full images with the iTerm2 protocol.
- Other terminals with 256 colors and Unicode get a preview drawn with colored blocks. Inside tmux, screen or Zellij the CLI also uses blocks.
- When none of these work, the CLI lists the image links instead.

Set `TRACING_IMAGES` to `kitty`, `iterm` or `blocks` to choose the method, or to `off` to turn images off. JSON mode never shows images.

The CLI sends your token only with image requests to your Tracing server's own file URLs. Images hosted anywhere else are fetched without it.
